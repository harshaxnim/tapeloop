Admin guide: deploying, configuring, inspecting and removing Tapeloop.

For Tapeloop 0.1.0. For people who manage Macs, and for power users. End users read the user guide; developers read the developer guide.

Installing

  1. Download Tapeloop-0.1.0.dmg and Tapeloop-0.1.0.dmg.sha256 from GitHub Releases into one folder, and check the DMG there: 
    shasum -a 256 -c Tapeloop-0.1.0.dmg.sha256
    It prints Tapeloop-0.1.0.dmg: OK when the file is intact.
  2. Copy the app out of the DMG: 
    hdiutil attach -nobrowse -readonly Tapeloop-0.1.0.dmg -mountpoint /Volumes/Tapeloop
sudo ditto /Volumes/Tapeloop/Tapeloop.app /Applications/Tapeloop.app
hdiutil detach /Volumes/Tapeloop
  3. Because the build is not notarized, Gatekeeper blocks the first launch of a downloaded copy. Remove the quarantine attribute, or have the user choose Open (macOS 14) or Open Anyway in System Settings › Privacy & Security (macOS 15 and later): 
    sudo xattr -dr com.apple.quarantine /Applications/Tapeloop.app
  4. Check the signature and the version: 
    codesign --verify --deep --strict --verbose=2 /Applications/Tapeloop.app
/Applications/Tapeloop.app/Contents/MacOS/Tapeloop --version

On first launch each user sees a five-step welcome guide that asks for the permissions below and offers to download the speech model for transcripts. Settings and the speech model are per user; nothing is installed system-wide besides the app bundle. The app itself does not contain the speech model; see The speech model to install it without each user downloading it.

Updates. Tapeloop has no updater. Install a new version by replacing the app bundle. Because each ad-hoc signed build has a different signature, macOS treats an update as a new app and the user must allow the permissions again. Settings, recordings and transcripts are kept.

Privacy permissions

Calendars, full accessCalendarCalendarsOptional: event titles
Speech RecognitionSpeechRecognitionSpeech RecognitionOptional: transcripts with Apple's engine only. The default engine, Parakeet, needs no permission.
Notifications(not TCC)System Settings › Notifications › TapeloopOptional: save confirmations, meeting prompts

Tapeloop does not use Screen Recording, Accessibility or Input Monitoring. Its global shortcuts use Carbon hot keys, which need no permission. Meeting detection reads Core Audio process information, which needs no permission.

macOS has no public way for an app to read the System Audio Recording decision. When it is denied, the tap delivers silence. Tapeloop's Settings therefore shows "Asked" after the prompt and "Allowed" only after it has heard sound from the system audio.

Resetting permissions

Quit Tapeloop first. Then, as the user:

tccutil reset Microphone io.github.harshaxnim.tapeloop
tccutil reset AudioCapture io.github.harshaxnim.tapeloop
tccutil reset Calendar io.github.harshaxnim.tapeloop
tccutil reset SpeechRecognition io.github.harshaxnim.tapeloop
# or all at once:
tccutil reset All io.github.harshaxnim.tapeloop

macOS asks again the next time Tapeloop uses each one. To show the system audio prompt again from Tapeloop's Settings or welcome guide, also remove its own "asked" flag: defaults delete io.github.harshaxnim.tapeloop systemAudioAsked.

Configuration profiles

Apple does not let a configuration profile (PPPC payload) grant microphone access; profiles can only deny it, so each user must allow the microphone. A PPPC payload also needs a code requirement, and an ad-hoc signed build's requirement changes with every build. Pre-approving Tapeloop's permissions through MDM is therefore not practical until releases are signed with a Developer ID. This has not been tested with an MDM server.

Presetting settings

There are no individual managed-preference keys. To give a user a starting configuration, quit Tapeloop, write the whole JSON document as data, and start Tapeloop again. Any field you leave out takes its default. Tapeloop rewrites the key whenever the user changes a setting, so this is a starting point, not an enforced policy. This method has not been tested on managed Macs.

defaults write io.github.harshaxnim.tapeloop appSettings -data \
  "$(printf '%s' '{"onboardingDone":false,"recorder":{"bufferDuration":3600}}' | xxd -p | tr -d '\n')"

To reset Tapeloop to its defaults (the welcome guide appears again): quit it, then defaults delete io.github.harshaxnim.tapeloop.

The rolling buffer itself is in memory and is never written anywhere unless disk use is allowed. A crash or a forced quit cannot delete the disk part; Tapeloop deletes it the next time it starts.

The sidecar JSON is pretty-printed with sorted keys and ISO-8601 UTC dates. Its fields are version, title, start, duration, sources, mixed, meeting, bookmarks and transcript; the architecture document has a full example.

Memory and disk sizing

Tapeloop plans memory as bit rate ÷ 8 × seconds × 1.03. The measured figure at 48 kbps is 20.0 MB per hour per source, a little below the plan.

QualityPer source, per hour2 h, both sourcesFits in 500 MB (both)
32 kbps14.8 MB59 MB16.9 h
48 kbps (default)22.2 MB89 MB11.2 h
64 kbps29.7 MB119 MB8.4 h
96 kbps44.5 MB178 MB5.6 h

The longest buffer a user can choose is 12 hours. Disk use is off by default; when a chosen length does not fit, Tapeloop asks the user. Under macOS memory pressure Tapeloop reduces the in-memory part to 50 % (warning) or 25 % (critical), oldest audio first.

Saved files: single-source and per-source saves keep the buffer's bit rate (no re-encoding); a mixed save is re-encoded once at 64 kbps mono, about 29 MB per hour.

Transcription with Parakeet adds 731 MB of disk space per user for the model, and about 0.8 GB of memory while the model is loaded: during each transcript in "after each save" mode, and the whole time Tapeloop records in live mode. Measured on an Apple M2: the model loads in about 0.2 s, and an 8-second recording is transcribed in about 1 to 1.5 s including the load.

The speech model

Parakeet transcription needs one model file. Tapeloop does not ship it in the app and never downloads it by itself.

File nameparakeet-unified-en-0.6b-Q8_0.gguf
Size731 357 568 bytes (731 MB)
SHA-2564b50b6dd862bf6e346929aaf4f5eaacec003bfa3f56462d6c874b41ef2f38795
Sourcehttps://github.com/harshaxnim/tapeloop/releases/download/models-v1/parakeet-unified-en-0.6b-Q8_0.gguf
Installed at~/Library/Application Support/Tapeloop/Models/ in each user's home folder

Users get the file in one of three ways: Download in the welcome guide or in Settings › Transcripts; Import File… in Settings › Transcripts; or a copy that you put in place. A download or an import is installed only if both the size and the SHA-256 match.

Pre-installing the model

Tapeloop treats the model as installed when the file is in the Models folder with exactly the expected size. It does not check the hash of a file you copy there, so check it yourself before you distribute it:

shasum -a 256 parakeet-unified-en-0.6b-Q8_0.gguf
# must print 4b50b6dd862bf6e346929aaf4f5eaacec003bfa3f56462d6c874b41ef2f38795

Then, for each user, with Tapeloop not running:

mkdir -p ~/Library/Application\ Support/Tapeloop/Models
cp parakeet-unified-en-0.6b-Q8_0.gguf ~/Library/Application\ Support/Tapeloop/Models/
  • Copy the real file. A symbolic link is not accepted, because Tapeloop checks the size of the item itself.
  • The file must be readable by the user. If you copy it as root, set its owner to the user.
  • Tapeloop reads the model state when it starts, so copy the file before Tapeloop runs, or quit and reopen it afterwards.
  • A pre-installed model does not turn transcription on. The user turns on Transcribe recordings in Settings › Transcripts, or you preset it (below). Only a download or an import that the user starts turns transcription on by itself.

To preset transcription with Parakeet after each save, include the transcription object with an explicit engine in the settings document (see Presetting settings):

defaults write io.github.harshaxnim.tapeloop appSettings -data \
  "$(printf '%s' '{"transcription":{"enabled":true,"engine":"parakeet","mode":"afterSave","labelSpeakers":true}}' | xxd -p | tr -d '\n')"

Offline Macs

On a Mac without internet access, pre-install the model as above (or let the user import the file with Import File…). Tapeloop then needs no network at all. Without the model, transcription works only with Apple's engine, for languages that macOS can recognise on the device.

Removing the model

The user clicks Delete… in Settings › Transcripts, or you delete the file with Tapeloop not running. Existing transcripts are kept. Parakeet transcription stops until the model is installed again.

Launch at login

Tapeloop registers itself as a login item with SMAppService.mainApp. The welcome guide's "Open Tapeloop when I log in" box is ticked by default; users change it later in Settings › General. The item appears in System Settings › General › Login Items, where it can also be turned off. To list background and login items from Terminal:

sudo sfltool dumpbtm | grep -i -A6 tapeloop

Registration can fail when the app runs from an unusual location; Tapeloop then asks the user to move it to the Applications folder.

Logs and diagnostics

Tapeloop writes to the unified log with subsystem io.github.harshaxnim.tapeloop. It writes no log files of its own.

# the last hour
/usr/bin/log show --info --last 1h --predicate 'subsystem == "io.github.harshaxnim.tapeloop"'
# live
/usr/bin/log stream --info --predicate 'subsystem == "io.github.harshaxnim.tapeloop"'
# one area, for example capture problems
/usr/bin/log show --info --last 1h --predicate 'subsystem == "io.github.harshaxnim.tapeloop" AND category == "system-audio"'

Capture self-test. open -W -n /Applications/Tapeloop.app --args --probe --seconds 10 --out /tmp/tapeloop-probe records 10 seconds of both sources through the installed app, writes probe-microphone.m4a, probe-system.m4a and report.txt, and ends the report with RESULT: OK when both sources worked. Quit the running Tapeloop first.

Network behaviour

Tapeloop has no telemetry, no crash reporting, no update checks and no cloud features. Audio, recordings and transcripts never leave the Mac. It makes exactly one kind of network request: downloading the speech model, and only when the user clicks Download (welcome guide or Settings › Transcripts) or Try Again after a failed download.

URLhttps://github.com/harshaxnim/tapeloop/releases/download/models-v1/parakeet-unified-en-0.6b-Q8_0.gguf
Hosts to allowgithub.com, which redirects to GitHub's release download hosts (at the time of writing release-assets.githubusercontent.com or objects.githubusercontent.com). HTTPS, port 443.
MethodOne HTTPS GET of a 731 MB file. No cookies or cache (an ephemeral session); macOS's system proxy settings apply. A request times out after 60 s without data; the whole download may take up to 6 hours.
ChecksAny answer other than HTTP 200 is rejected. The file is installed only if its size and SHA-256 match the values built into the app.

All network code is in one source file, Sources/TapeloopParakeet/ModelDownloader.swift. The project's CI fails any build in which URLSession, NWConnection, URLRequest, CFSocket or NSStream appears in any other source file. Apple's speech engine requires on-device recognition and never falls back to Apple's servers. The other web addresses in the app are links in Settings › About, which open in the user's browser when clicked.

There is no setting that hides the Download button. To keep Macs from downloading the model, block the URL above at your proxy or firewall (blocking all of GitHub's release download hosts also affects other software), or pre-install the model so the button is not shown. To confirm what the running app has open:

lsof -nP -i -a -p "$(pgrep -x Tapeloop)"

An empty result means no network connections. While a model download runs, it shows HTTPS connections to GitHub.

Uninstalling

  1. In Tapeloop, turn off Settings › General › "Open Tapeloop when I log in" (or remove it in System Settings › General › Login Items).
  2. Quit Tapeloop from its menu. Quitting erases the buffer and the disk part.
  3. Remove the app, its settings, its cache folder and its permissions: 
    rm -rf /Applications/Tapeloop.app
defaults delete io.github.harshaxnim.tapeloop
rm -rf ~/Library/Caches/io.github.harshaxnim.tapeloop
rm -rf ~/Library/Application\ Support/Tapeloop   # the speech model, 731 MB
tccutil reset All io.github.harshaxnim.tapeloop
  4. Recordings are the user's files and are not removed. Delete ~/Music/Tapeloop (or the chosen folder), including its hidden .tapeloop folder, only if the user wants them gone.
