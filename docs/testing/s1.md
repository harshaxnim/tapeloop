# Mac test for step s1: the build, the menu bar shell, and the audio probe

Goal: prove on the real Mac (macOS 14.6, Xcode 16.2) that the project builds from source, that the menu bar app
shows the cassette, and, most important, that **system audio capture through a Core Audio process tap works**.

## 1. Build from source

```bash
cd ~/myapps/tapeloop && git pull
xcode-select -p            # expect the Xcode 16.2 developer folder
swift --version            # expect Swift 6.0.x
make test                  # expect all tests to pass (core + encode/write test)
make app                   # builds build/Tapeloop.app for this Mac's architecture
```

Expect: no errors. `make test` prints `encoded 10 s in NNNNN bytes` (around 60 000).

## 2. The menu bar app

```bash
open build/Tapeloop.app
```

- [ ] A cassette outline appears in the menu bar, with small **pause bars** between its reels (it starts paused in s1).
- [ ] It is crisp and readable in both light and dark menu bars (System Settings > Appearance).
- [ ] Left click opens a popover: status "Paused", a memory figure ("Zero KB" for now), the "in memory only" text,
      **Resume** and **Quit Tapeloop**.
- [ ] Click **Resume**: the icon changes to the cassette with a **solid dot** in its top-right corner; the popover
      says "Recording to memory". (s1 does not capture yet; this only checks the icon states.)
- [ ] Right click opens a menu: Save Last 5 Minutes, Bookmark Moment (both greyed out in s1), Pause/Resume
      Recording (works), Library…, Settings… (greyed out), Quit Tapeloop (works).
- [ ] No Dock icon appears.
- [ ] Quit from the menu.

## 3. The audio probe (the riskiest part)

Start some sound first (for example a YouTube video in the browser), and speak while the probe runs.

```bash
make probe                 # runs the app bundle for 10 s in probe mode, then prints the report
```

- [ ] macOS asks for **Microphone** access for Tapeloop. Allow.
- [ ] macOS asks for **System Audio Recording** access ("Tapeloop would like to record this computer's audio").
      Allow. If no prompt appears, check System Settings > Privacy & Security > Screen & System Audio Recording
      (the "System Audio Recording Only" list) and note what you see.
- [ ] The report ends with `RESULT: OK`, and for each of `microphone` and `system` shows buffers > 0, about 10 s
      encoded, **about 60 000 bytes in RAM** (raw PCM would be about 1 900 000), and a peak level above -40 dBFS.
- [ ] `open build/probe/probe-microphone.m4a` plays your voice; `open build/probe/probe-system.m4a` plays the video's
      sound. Both are about 10 s long.

If the first run was denied or showed `WARN ... only silence`, grant the permission in System Settings and run
`make probe` again. Please copy the full report into the findings.

## 4. Logs

```bash
log show --predicate 'subsystem == "io.github.harshaxnim.tapeloop"' --last 10m --info
```

Expect lines from categories `app` ("Tapeloop started", "Status: recording"), `mic` ("Mic format: …"),
`system-audio` ("Tap format: …", "System audio tap started"), and `probe` (the report lines). Any `error` line is a
finding.

## 5. The DMG from CI (optional)

Download `Tapeloop-dmg` from the latest green CI run (Actions tab), open the DMG, drag Tapeloop to Applications,
then right-click > Open (it is ad-hoc signed and not notarized), or run
`xattr -dr com.apple.quarantine /Applications/Tapeloop.app`. The cassette should appear as in section 2.
